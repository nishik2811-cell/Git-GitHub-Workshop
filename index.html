1. What is Git?

Git is a save button for your whole project.

Think of a video game. You save at a good moment, and if you mess up later, you load that save and carry on. Git does exactly this, but for your files.

CommitOne save point. It carries a short note like "add results".
RepositoryYour project folder, being watched by Git. People say "repo".
HistoryThe list of every save point, newest first.

P1_04_CENTRALIZED-VS-DISTRIBUTED.EXE

4. Centralized vs Distributed Version Control Systems

Where does the history live? In one place, or everywhere?

Imagine a library book. In a centralized system there is one copy and everyone must queue for it. In a distributed system everyone owns a full photocopy of the whole book.

Centralized
One server holds the history. Everyone else has only the latest files.
Distributed (Git)
Everyone has the full history on their own laptop.

CentralizedDistributed (Git)
Server breaksNobody can save historyEveryone still has everything
No internetVery limitedKeep saving, upload later
BackupsOne copy to protectEvery copy is a backup
Git is distributed, so it is safer and works offline.

5. Git and GitHub setup and installation

Six small steps. No experience needed.

Press Next on each screen, like an installer. Try it before the session. We will also do it together.

Step 1: Meet the terminal

A terminal is a window where you type instructions (called commands) instead of clicking.

Click the Start button, type Git Bash and press Enter. (You will install it in the next step. Until then you can use Command Prompt.)

Press Cmd + Space, type Terminal, press Enter.

Press Ctrl + Alt + T, or search your apps for Terminal.

pwdWhich folder am I in?
lsList the files here
cd nameGo into a folder
GIT BASH / TERMINAL
# lines starting with # are notes, do not type them
$ git --version
git version 2.xx.x

The $ is just the terminal waiting for you. Do not type it. Type the rest and press Enter.

Step 2: Install Git

Pick your computer type and follow the numbers.

1

Go to git-scm.com/download/win. The download starts by itself. If not, click "Click here to download".

2

Open the downloaded file (Git-2.xx.x-64-bit.exe). If Windows asks "Do you want to allow this app to make changes?" click Yes.

3

You will see many screens. On almost all of them, just click Next. The default choices are fine.

4

One screen is worth reading: "Adjusting the name of the initial branch". Pick "Override..." and keep the name main.

5

Click Install, wait for the green bar, then Finish.

6

Click Start, type Git Bash, press Enter. That black window is your terminal for the whole workshop.

1

Open Terminal: Cmd + Space, type Terminal, Enter.

2

Type git --version and press Enter.

3

If a box asks about the command line developer tools, click Install and wait a few minutes.

4

Type git --version again. A version number means you are done.

5

Optional: if you use Homebrew, brew install git also works.

1

Open the terminal: Ctrl + Alt + T.

2

Type sudo apt update and press Enter. Type your password when asked. Nothing shows while you type it, and that is normal.

3

Type sudo apt install git, press Enter, and type y when it asks. (Fedora: sudo dnf install git.)

4

Check with git --version.

Step 3: Check that it works

Open your terminal and type the command, then press Enter.

GIT BASH / TERMINAL
$ git --version
git version 2.43.0
You see "git version ..."Perfect! Go to the next step. Your numbers may differ, that is fine.
You see an errorClose the terminal and open a new one. Still stuck? See the last step.

Step 4: Make a GitHub account

This happens in your web browser. It is free.

1

Go to github.com and click Sign up.

2

Type your email, make a password, pick a username.

3

Solve the small puzzle, then type the code GitHub emails you.

4

Choose the Free plan. Skip any extra questions.

Your username is public and appears in your project links, so pick something you are happy to show.

Step 5: Tell Git who you are

Every save point is signed with a name and email. You do this once per computer. Change the name and email to yours.

GIT BASH / TERMINAL
$ git config --global user.name "Nishita Kumari"
$ git config --global user.email "you@example.com"
$ git config --global init.defaultBranch main

Nothing is printed when it works. No news is good news. To double check:

GIT BASH / TERMINAL
$ git config --list
user.name=Nishita Kumari
user.email=you@example.com
init.defaultbranch=main
Use the same email as your GitHub account. The first time you upload, a browser window opens to sign in. Click Authorize. Your account password will not work in the terminal.

Step 6: Checklist and fixes

Tick everything off. If something went wrong, open a problem box.

Tick what you have done

Common problems. Click one.

"git is not recognized" / "command not found"
Close every terminal and open a new one. On Windows use Git Bash. Still failing? Run the installer again with the recommended choices.
"Please tell me who you are"
You skipped the name and email step. Run the two git config --global commands.
A box asks for developer tools (Mac)
Normal. Click Install and wait, then run git --version.
The GitHub email never arrived
Check spam, wait a minute, click Resend, and check the email you typed.
Password rejected when pushing
Use the browser sign-in window that opens. If there is none, create a personal access token in GitHub Settings, Developer settings.

P2_04_PUSH-PULL-AND-CLONE.DOC

4. Push, Pull and Clone

Your laptop and GitHub are two copies. These commands post work between them.

git pushPost your new commits UP to GitHub.
git pullBring new commits DOWN from GitHub.
git cloneDownload a whole project for the first time.

Your first push, step by step

1

On GitHub, create a new repo. If your project already has commits, leave "Add a README" unticked.

2

Click the green Code button and copy the web address.

3

In your terminal, inside your project folder: git remote add origin PASTE-THE-ADDRESS

4

Name your branch main: git branch -M main

5

Upload: git push -u origin main. A browser window may open. Click Authorize.

6

Refresh the GitHub page. Your files are there!

Cloning is easier. The link comes from the green Code button:

GIT BASH / TERMINAL
$ git clone https://github.com/user/recipes.git
Cloning into 'recipes'... done.
$ cd recipes
$ git pull
Already up to date.
Push = upload. Pull = download the latest. Clone = download everything once.
P2_05_UNDERSTANDING-REMOTE-REPOSITORIES.EXE

5. Understanding remote repositories

A remote is the online copy, saved in your contacts under a nickname.

The usual nickname is origin. Your laptop even remembers where GitHub was the last time you checked, as origin/main.

git remote -vShow my remotes and their addresses.
git fetchCheck what is new online, but do not touch my files.
git pullFetch, and also bring the new work into my files.
git push -u origin main uploads and remembers the link. After that, plain git push and git pull know where to go.
Remote = the online copy. origin = its nickname.

P3_01_INTRODUCTION-TO-BRANCHES.TXT

1. Introduction to branches

A branch is a draft copy where you can experiment safely.

You wrote a perfect essay and want to try a risky new ending. You would not edit the only copy. You would make a draft. If the ending is great, you keep it. If not, you throw the draft away.

SafeWhatever you break on a branch never touches main.
ParallelEach teammate works on their own branch at the same time.
main is the official version. Branches are side roads.
P3_02_CREATING-AND-SWITCHING-BRANCHES.GIF

2. Creating and switching branches

Three commands. That is all.

git branchList my branches. The * marks where I am.
git switch -c nameMake a new branch and move onto it.
git switch nameMove to a branch that already exists.
GIT BASH / TERMINAL
$ git branch
* main
$ git switch -c feature/login
Switched to a new branch 'feature/login'
$ git branch
* feature/login
  main
$ git switch main
Switched to branch 'main'
No spaces in branch names. Use dashes: add-login-page. Older guides use git checkout -b, which does the same job.

P4_01_GITIGNORE.TXT

1. Understanding .gitignore

.gitignore is the list of things you do not pack in the suitcase.

Secret passwords, huge files, junk your tools create. List them in a plain text file named .gitignore and Git pretends they do not exist.

TRY IT: ignore some files

Click a file to ignore or un-ignore it.

LineMeaning
.envIgnore this exact file
*.logIgnore every file ending in .log
node_modules/Ignore this whole folder
Create it before your first commit. A secret that was already committed stays in the history, even if you delete the file later.
